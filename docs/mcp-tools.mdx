The server serves MCP over stdio and opens no network port. Harnesses with a knowledge-mcp plugin start the server through the plugin. Other harnesses run `kb mcp`.

{/* END AUTO-GENERATED intro */}

> Generated regions come from [tools.json](https://github.com/SterlingJF/knowledge-mcp/blob/main/contracts/extensions/mcp/v1/tools.json), the `tools/list` response. After a tool change, run `just generate_contract_snapshots`, then `just generate_mcp_tools_doc`.

## File access and side effects

The agent supplies document text, inventories and configuration, then applies prepared file changes with its own tools. Preparation tools return text for the agent to save; tool calls also append answers to the state log. `kb_record_edit` stores edit history there, and `kbp_explore` writes offline viewers. See [data handling and retention](https://github.com/SterlingJF/knowledge-mcp/blob/main/SECURITY.md#trust-model).

The included [writing skill](https://github.com/SterlingJF/knowledge-mcp/blob/main/runtime/skills/kb-write-document/SKILL.md) and [tracking skill](https://github.com/SterlingJF/knowledge-mcp/blob/main/runtime/skills/kb-track-document-types/SKILL.md) cover approval, link searches, configuration checks, applying changes and guarded undo. The [naming and filing guide](/naming-and-filing) explains the workflow for readers.

When kbp runs, the result contains one text block per non-empty stream, with stdout before stderr.
Each block identifies the stream in `_meta.stream`.
Tools with a `folders` argument can append a JSON text block with `_meta.stream` set to `knowledge-mcp`.
That block lists bundled or received universe specs and, after a successful `kbp_explore` call, the `explorer` folder.
The result contains the kbp exit code in `_meta.exit_code` and sets `isError` for a non-zero exit code.

`kb_prepare_proposal`, `kb_record_edit` and `kb_list_edits` also return a Markdown card in `card`, repeated as the first text block, for harnesses that pass only one of the two to the model.

Failures in `kb_*` tools and errors before kbp runs return a problem object in `structuredContent`.
[problem.schema.yaml](https://github.com/SterlingJF/knowledge-mcp/blob/main/contracts/extensions/mcp/v1/problem.schema.yaml) lists the problem types.

## Terms

| Term          | Meaning                                                                                 |
| ------------- | --------------------------------------------------------------------------------------- |
| universe spec | A `*.kbp.yaml` file that declares document types and their questions                    |
| card          | A summary from `kbp_card` with sections, questions and conditions for one document type |
| kind          | In `kbp_card`, a document type id. In `kbp_mint`, the category of code to mint          |
| actor         | The role that uses a document type, such as maintainer                                  |
| element       | A question answered by a document section                                               |
| artifact      | A document type declared in a universe spec                                             |
| frame         | A setting used to order, select or require document types and sections                  |
| factor        | A question you can use to choose writing advice without changing document structure     |
