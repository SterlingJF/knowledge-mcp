# server

The engine: an offline HTTP API over a folder of Markdown files, frozen as `km-server`.

## Layout

```text
server/
├── README.md
├── pyproject.toml
├── km-server.spec               freezes dist/km-server; the caller names the knowledge-model folder
├── .gitignore
├── app/
│   ├── factory.py               create_app(): routers, middleware, error handlers, knowledge model
│   ├── settings.py              KM_* environment settings
│   ├── config.py                remembered vaults in ~/.config/knowledge-mcp/config.json
│   ├── context.py               who is asking: the local person or a declared agent
│   ├── dependencies.py          request dependencies
│   ├── errors.py                KmError -> {detail, errorCode, fields}
│   ├── roles.py                 routers per role
│   ├── api_models_auto.py       generated by datamodel-codegen (never edit)
│   ├── entrypoints/desktop.py   km-server entry point
│   ├── knowledge_model/         loads universes and guidance
│   ├── middleware/              request logging
│   ├── routers/                 artifacts, files, universes, vaults, storage, health
│   ├── store/                   artifact files: codec, file store, validation, vaults
│   ├── vault/                   vault folder layout
│   ├── types/url.py             URL validator for the generated models
│   └── utilities/               atomic writes, logging
└── tests/
    ├── conftest.py
    ├── test_artifacts_api.py
    ├── test_codec.py
    ├── test_config_and_storage.py
    ├── test_files_api.py
    ├── test_store_and_roles.py
    └── test_vault.py
```

## Commands

| Command                                                                                                                  | Purpose                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `uv run --locked python -m app.entrypoints.desktop --knowledge-model-dir <folder>`                                       | Start the engine with `<folder>` as its knowledge model                                       |
| `KM_KNOWLEDGE_MODEL_DIR=../contracts/extensions/knowledge-bus/upstream uv run --locked pytest`                           | Run the tests                                                                                 |
| `uv run --locked --exact --group build pyinstaller --noconfirm --clean km-server.spec -- --knowledge-model-dir <folder>` | Freeze `dist/km-server` with `<folder>` bundled as its knowledge model                        |
| `just check_server`                                                                                                      | From the repo root: lint, format-check, and test with the vendored knowledge model, as in CI  |
| `just build_sidecars`                                                                                                    | From the repo root: freeze both binaries into the launcher, with the vendored knowledge model |

Run from source, the engine needs `--knowledge-model-dir` or `KM_KNOWLEDGE_MODEL_DIR`. A frozen `km-server` bundles its knowledge model at build time. The tests need the vendored knowledge model.
